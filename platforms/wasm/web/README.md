# CrabBoy Web Frontend (WASM)

A minimal web frontend for the CrabBoy Game Boy emulator. It loads a `.gb` ROM,
renders the framebuffer to a `<canvas>`, and provides pause/resume plus basic
keyboard controls. **No audio and no save-state UI in this iteration.**

## Layout

- `index.html` — page structure (load input, canvas, pause button, hint).
- `index.js` — ES module; boots the wasm module, drives the rAF loop, renders
  each frame, and maps keys to `Gb.set_button(mask, pressed)`.
- `style.css` — dark styling, centered pixelated canvas.
- `pkg/` — generated by the build; **do not commit**.

## Requirements

- Rust with the `wasm32-unknown-unknown` target:
  `rustup target add wasm32-unknown-unknown`
- `wasm-bindgen-cli` (this repo's version: 0.2.127). Optionally `wasm-pack`.

## Build

From the workspace root (`D:\Projects\CrabBoy`):

```powershell
# 1. Compile the wasm bindings (gated behind the `wasm` feature).
cargo build -p crab-wasm --features wasm --release --target wasm32-unknown-unknown

# 2. Generate the JS glue into web/pkg (--target web matches the hand-written JS import).
wasm-bindgen target/wasm32-unknown-unknown/release/crab_wasm.wasm `
  --target web `
  --out-dir platforms/wasm/web/pkg
```

Alternatively, if you have `wasm-pack` installed, one command produces the same
`web/pkg` output (and drops the `.gitignore` in `pkg/`):

```powershell
wasm-pack build platforms/wasm --target web --features wasm --out-dir web/pkg
```

## Run

Serve the `web/` folder over HTTP (ES modules + fetch of the `.wasm` require a
server, not `file://`). From `platforms/wasm/web`:

```powershell
python -m http.server 8000
```

Then open http://localhost:8000, click **Load ROM (.gb)**, pick a Game Boy ROM,
and press Pause/Resume to control playback.

## Controls

| Key        | Action     |
|------------|------------|
| Arrows     | D-pad      |
| Z          | A          |
| X          | B          |
| Enter      | Start      |
| Backspace  | Select     |

## Notes

- The Rust crate `crab-wasm` (`platforms/wasm/Cargo.toml`) gates all
  `wasm-bindgen` code behind the `wasm` feature, which is **not** in `default`,
  so native/workspace builds are unaffected. No extra wasm-only Rust deps were
  added here.
- Button bitmasks match `gb_core::joypad` (re-exported at the crate root), so
  `gb_core::joypad::BUTTON_A` etc. resolve correctly.
