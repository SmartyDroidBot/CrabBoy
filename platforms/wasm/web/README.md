# CrabBoy web frontend

A minimal browser frontend for CrabBoy. It runs the same `crab-systems`
cores as the desktop build through WebAssembly: drop a `.gb`, `.gbc` or
`.gba` file on the page and it plays with sound, keyboard, gamepad and
on-screen touch controls. Battery saves and a quick-save slot are kept in
the browser's IndexedDB, keyed by the ROM contents.

A build with the 3DS core (`--features ctr`, below) also opens decrypted
3DS card images (`.3ds`, `.cci`), program contents (`.cxi`) and 3DSX
homebrew. The browser holds the image in memory, so it takes images up to
1 GiB; the desktop build reads larger ones from disk.

Every file here is plain HTML, CSS and JavaScript (ES modules); there is no
bundler and no npm dependency.

## Layout

- `index.html`, `style.css` — page and styling.
- `index.js` — boots the wasm module, paces emulation with
  `requestAnimationFrame`, renders the RGBA framebuffer straight from wasm
  memory, and wires input, audio and saves.
- `audio-worklet.js` — ring-buffer `AudioWorkletProcessor` that plays the
  emulator's interleaved stereo samples at the console's native rate.
- `pkg/` — generated by `wasm-bindgen` (not committed).

## Build

Requirements: Rust with the `wasm32-unknown-unknown` target and
`wasm-bindgen-cli` at the version pinned in `Cargo.lock` (0.2.127):

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.127 --locked
```

From the repository root:

```sh
cargo build -p crab-wasm --release --target wasm32-unknown-unknown
wasm-bindgen --target web --out-dir platforms/wasm/web/pkg \
  target/wasm32-unknown-unknown/release/crab_wasm.wasm
```

Add `--features ctr` to the `cargo build` for the 3DS core.

## Run

ES modules and `.wasm` fetches need an HTTP server, not `file://`:

```sh
cd platforms/wasm/web
python -m http.server 8000
```

Open <http://localhost:8000> and load a ROM. The released `crabboy-<version>-web.zip`
contains this directory with `pkg/` already generated, and the same files are
deployed to GitHub Pages on every release.

## Controls

| Key               | Action                 |
|-------------------|------------------------|
| Arrows            | D-pad                  |
| Z / X             | A / B                  |
| Enter / Backspace | Start / Select         |
| A / S             | L / R                  |
| C / V             | X / Y (3DS)            |
| Q / W             | ZL / ZR (3DS)          |
| I / J / K / L     | Circle pad (3DS)       |
| Pointer           | Stylus (3DS, bottom screen) |
| P                 | Pause                  |
| R                 | Reset                  |
| F (hold)          | Fast-forward           |
| F5 / F9           | Quick save / load      |

Gamepads use the browser's standard mapping; for the 3DS the left stick is
the circle pad. On touch devices an on-screen pad appears below the screen
(L and R for GBA and 3DS games, X, Y, ZL and ZR for 3DS games).

## Headless test

`tests/run.js` runs a ROM under Node and prints the same FNV-1a-32 frame
hash as `crab run --hash`, so wasm and native output can be compared:

```sh
wasm-bindgen --target nodejs --out-dir target/wasm-node \
  target/wasm32-unknown-unknown/release/crab_wasm.wasm
node platforms/wasm/tests/run.js path/to/game.gb --frames 560 --input START@400 --hash
crab run path/to/game.gb --frames 560 --input START@400 --hash
```

The scripts take the same grammar as `crab run --input`, including the 3DS
stylus (`TOUCH:X:Y@F`, `!TOUCH@F`) and circle pad (`CPAD:X:Y@F`, `!CPAD@F`).
